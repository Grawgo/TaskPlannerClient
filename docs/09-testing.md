# Проверка приложения

Исходные проверки выполнены 27.09.2026, повторная проверка — 03.10.2026.
Android-клиент проверен на эмуляторе `Medium_Phone_API_35`; сервер —
с локальной PostgreSQL 17. Исторические ручные проверки и результаты
повторного запуска разделены ниже.

## Выполненные проверки

| № | Сценарий | Ожидаемый результат | Фактический результат и подтверждение |
|---:|---|---|---|
| 1 | Чистая сборка Android-клиента | Отладочный APK создаётся без ошибок | APK собран, `:app:assembleDebug` завершился успешно. |
| 2 | Чистая сборка Ktor-сервера | Сервер и тесты компилируются | `clean test build` завершился успешно; 4 интеграционных теста пройдены. |
| 3 | Запуск сервера с локальной БД | Ktor подключается к PostgreSQL и применяет миграции | Подключение установлено; Flyway подтвердил версию схемы 1. |

| 9 | Изменение статуса задачи | `DONE` ставит время завершения, возврат в `TODO` очищает его | Подтверждено тестами `taskLifecycleAndOwnerIsolation` и `dueDatesSortWithUnscheduledTasksLastAndCompletionCanBeReverted`. |
| 10 | Удаление задачи | Владелец удаляет задачу; повторное чтение даёт `404` | Подтверждено тестом `taskLifecycleAndOwnerIsolation`. |

| 12 | Поиск спецсимвола `%` | Символ трактуется буквально | Запрос `100%` нашёл задачу `100% готово`; тест `validationAndLiteralSearch` пройден. |
| 13 | Сортировка по сроку | Задачи без срока находятся после задач со сроком | Подтверждено для прямого и обратного порядка интеграционным тестом. |
| 14 | Валидация API | Пустое название, неверный лимит и идентификатор дают `400` | Все три случая подтверждены тестом `validationAndLiteralSearch`. |
| 15 | HTTP-запрос Android-клиента | Retrofit кодирует запрос и отправляет Bearer-токен | Тест `sendsEncodedSearchAndBearerTokenToHttpApi` получил закодированный запрос и заголовок. |

| 17 | Сессия приложения | Вход сохраняет сессию; истёкший токен обновляется; выход очищает её | Три теста `FirebaseAuthRepositoryTest` пройдены с тестовым API и хранилищем. |
| 18 | Ответ на устаревший поиск | Старые результаты не заменяют новый запрос; выход очищает результаты | Подтверждено тестом `editingQueryDiscardsLateResultsAndPreservesTextInSavedState`. |
| 19 | Ошибка поиска и повтор | Ошибка показывается; повтор отправляет тот же запрос; история пополняется после открытия результата | Подтверждено тестом `retryUsesSameQueryAndHistoryIsSavedOnlyAfterOpeningResult`. |
| 20 | История поиска Room | Хранятся 10 последних запросов, повторный выбор поднимается наверх, данные UID разделены, очистка работает | Инструментальный тест `SearchHistoryDaoTest` пройден на эмуляторе. |
| 21 | Поворот и очистка поиска | Введённый текст сохраняется после поворота; очистка возвращает пустое состояние | UI-тест `SearchScreenUiTest` пройден на эмуляторе. |

| 24 | Вход с реальным Firebase-аккаунтом | Android открывает список задач после входа | Временный аккаунт создан через Firebase API; вход выполнен на эмуляторе, список задач открыт. |
| 25 | Сквозное создание и повторное чтение | Android отправляет задачу через Ktor; PostgreSQL хранит запись; после повторного запуска задача видна | Через Android созданы две задачи; API вернул обе, PostgreSQL содержала две строки; после перезапуска приложение показало первую задачу. |
| 26 | Обновление списка после возврата | Сохранённая задача сразу появляется на главном экране | При первой проверке выявлено отсутствие обновления; исправлено и повторно проверено на второй задаче. |
| 27 | Выход из аккаунта | Сессия очищается, задачи скрываются до следующего входа | После выхода на эмуляторе показан экран входа вместо задач. |
| 28 | Подключение физического телефона | Отладочная сборка через USB получает задачи от локального Ktor-сервера | На Samsung SM-G950F (Android 9 / API 28) после `adb -d reverse tcp:8080 tcp:8080` ошибка соединения исчезла, экран задач загрузился. |

## Повторная проверка 03.10.2026

Пройдено **15 модульных тестов клиента**, **4 интеграционных и 5 модульных
тестов сервера**, а также **4 инструментальных теста Android**,
из них 3 UI-теста. Ошибок и пропущенных тестов нет.

| Проверка | Результат |
|---|---|
| Сборка APK и тестового APK | Успешно |
| Android Lint | Ошибок нет; 7 предупреждений о настройках, неиспользуемых ресурсах и стиле |
| Полный повторный запуск серверных тестов | Успешно, 9 тестов |
| Загрузка списка длиннее одной страницы | Проверены 73 задачи, запросы с offset 0 и 50 сохраняют фильтр |
| Обнаружение сервера | Модульные UDP-тесты клиента и сервера пройдены |
| Проверка работающего сервера по Wi-Fi адресу | Получен ответ обнаружения, health = 200, задачи без токена = 401 |
| Room и поворот поиска | Инструментальные тесты пройдены |
| Переходы вход → регистрация → сброс пароля | UI-тест пройден; переход к входу через настройки учитывает прокрутку |
| Длинное описание на коротком экране | UI-тест подтвердил доступность и действие кнопки удаления после прокрутки |

При проверке исправлены ограничение клиента первыми 50 задачами,
отсутствие фильтра по приоритету, прокрутка длинных экранов и обновление
результатов поиска после возврата из деталей. Повторная проверка не
включала полный ручной сценарий регистрации через экран Android и запуск
на физическом телефоне по Wi-Fi.

Отчёты JUnit создаются в `app/build/test-results/testDebugUnitTest/` клиента
и `build/test-results/test/` сервера. Инструментальные результаты находятся
в `app/build/outputs/androidTest-results/connected/debug/`, отчёт Lint —
в `app/build/reports/lint-results-debug.html`. При повторной проверке
использована Gradle-задача `connectedDebugAndroidTest`.

Команда проверки Android-клиента при запущенном эмуляторе:

```bash
./gradlew :app:testDebugUnitTest :app:connectedDebugAndroidTest :app:lintDebug :app:assembleDebug
```

## Границы выполненных проверок

| Сценарий | Ожидаемый результат | Состояние |
|---|---|---|
| Регистрация через экран Android | Firebase создаёт аккаунт и сразу открывает приложение | Проверен вход в уже созданный временный аккаунт; регистрация через интерфейс Android ещё не проверена. |
| Физический телефон без USB | Автоматически находит Ktor и выполняет действия с задачами в общей Wi-Fi сети | Обнаружение и API проверены с ноутбука; полный сценарий на физическом телефоне по Wi-Fi ещё не выполнен. |

Firebase используется только для аутентификации. Тестовые UID серверных
интеграционных тестов выдаёт подставной `TokenVerifier`; для сквозной
проверки использован реальный Firebase ID-токен. Временные аккаунты и
задачи после проверки удалены. Данные задач сохраняются в PostgreSQL.
