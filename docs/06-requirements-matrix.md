# Матрица требований курсовой

Правило приоритета от заказчика: при расхождении фотографии имеют
приоритет над общей методичкой. Этот документ фиксирует решения до начала
реализации, чтобы клиент, сервер и пояснительная записка описывали одну
систему.

| Требование | Источник | Проектное решение | Проверка позднее |
|---|---|---|---|
| Клиент-серверное приложение | Фото 4, 7; методичка, с. 32 | Android → Ktor REST → PostgreSQL | Создание задачи и повторное чтение после перезапуска |
| Весь код на Kotlin | Методичка, с. 32 | Android и Ktor на Kotlin | Исходники двух проектов |
| Ktor на сервере | Фото 4, 5, 7 | Ktor | Запуск сервера и API-тест |
| Собственная БД | Фото 4, 5, 7 | PostgreSQL, таблицы `app_users` и `tasks` | Миграция и данные в БД |
| Локальная и удалённая БД | Фото 4 и 7 | Локальная PostgreSQL при разработке, PostgreSQL в Neon для показа | Настройки двух сред |
| Firebase для email/password | Фото 5, 6, 7 | Только Firebase Authentication; задачи в PostgreSQL | Регистрация, вход, проверка токена сервером |
| Запрет Firebase как хранилища | Фото 4, 5 | Firestore и Realtime Database не используются | Проверка зависимостей и данных |
| Compose и Material Design | Фото 4, 6, 7 | Compose UI по макетам | Сравнение экранов с макетами |
| Clean Architecture | Фото 4, 6, 7 | `data`, `domain`, `presentation` на клиенте | Структура пакетов и зависимости |
| Hilt | Фото 7 | Внедрение зависимостей клиента | Сборка и тесты |
| Retrofit или Ktor-клиент | Фото 5 | Retrofit | Реальный запрос к Ktor |
| Room | Фото 7 | Локальная история поиска | Повторный запуск приложения |
| Регистрация и вход | Методичка, с. 32 | Два отдельных экрана | UI-сценарии |
| Поиск с очисткой и сохранением при повороте | Методичка, с. 32–33 | Экран поиска, состояние ViewModel/SavedStateHandle | UI-тест поворота |
| История до 10 запросов | Методичка, с. 33 | Room, записи после открытия результата | UI- и модульные тесты |
| Загрузка, пустой результат, ошибка и «Обновить» | Методичка, с. 33 | Состояния экрана поиска | UI-тесты |
| Тёмная тема | Методичка, с. 33 | Переключатель и DataStore | Повторный запуск в тёмной теме |
| Модульные и UI-тесты | Фото 7 | Автоматические тесты клиента и сервера | Отчёты о тестах |
| Две публичные ссылки | Фото 4, 7 | Отдельные репозитории клиента и сервера | Ссылки перед сдачей |

Методичка на с. 34 запрещает Firebase полностью, но по заданному
приоритету фотографий используется Firebase Authentication. Требование
собственной БД и сервера при этом сохраняется: они хранят и обрабатывают
задачи, а Firebase лишь подтверждает личность пользователя.
