# Матрица требований курсовой

Источники требований — методические указания и дополнительные материалы
задания. Дополнительные требования имеют приоритет при расхождениях
с методичкой. Материалы задания содержат два варианта размещения БД:
локальный и удалённый. Реализована локальная PostgreSQL на ноутбуке;
удалённый вариант в текущую конфигурацию не входит.

Матрица связывает требования с компонентами проекта и способами проверки.
Результаты приведены в [протоколе тестирования](09-testing.md).

| Требование | Источник | Проектное решение | Способ проверки |
|---|---|---|---|
| Клиент-серверное приложение | Дополнительные требования; методичка, с. 32 | Android → Ktor REST → PostgreSQL | Создание задачи и повторное чтение после перезапуска |
| Весь код на Kotlin | Методичка, с. 32 | Android и Ktor на Kotlin | Исходники двух проектов |
| Ktor на сервере | Дополнительные требования | Ktor | Запуск сервера и API-тест |
| Собственная БД | Дополнительные требования | PostgreSQL, таблицы `app_users` и `tasks` | Миграция и данные в БД |
| Размещение БД | Дополнительные требования: локальный и удалённый варианты | Выбрана локальная PostgreSQL на ноутбуке | Конфигурация сервера и запуск с PostgreSQL |
| Firebase для email/password | Дополнительные требования | Только Firebase Authentication; задачи в PostgreSQL | Регистрация, вход, проверка токена сервером |
| Запрет Firebase как хранилища | Дополнительные требования | Firestore и Realtime Database не используются | Проверка зависимостей и данных |
| Compose и Material Design | Дополнительные требования | Compose UI, Material 3, локальные макеты | Сборка и UI-тесты |
| Макет в Figma | Методичка, с. 32 | Локальные макеты PNG; файл Figma отсутствует | Наличие файла Figma |
| Clean Architecture | Дополнительные требования | `data`, `domain`, `presentation` на клиенте | Структура пакетов и зависимости |
| Hilt | Дополнительные требования | Внедрение зависимостей клиента | Сборка и тесты |
| Retrofit или Ktor-клиент | Дополнительные требования | Retrofit | Реальный запрос к Ktor |
| Room | Дополнительные требования | Локальная история поиска | Повторный запуск приложения |
| Регистрация и вход | Методичка, с. 32 | Два отдельных экрана | UI-сценарии |
| Поиск с очисткой и сохранением при повороте | Методичка, с. 32–33 | Экран поиска, состояние ViewModel/SavedStateHandle | UI-тест поворота |
| История до 10 запросов | Методичка, с. 33 | Room, записи после открытия результата | UI- и модульные тесты |
| Загрузка, пустой результат, ошибка и «Обновить» | Методичка, с. 33 | Состояния экрана поиска | UI-тесты |
| Тёмная тема | Методичка, с. 33 | Переключатель и DataStore | Повторный запуск в тёмной теме |
| Модульные и UI-тесты | Дополнительные требования | Автоматические тесты клиента и сервера | Отчёты о тестах |
| Две публичные ссылки | Дополнительные требования | Отдельные репозитории клиента и сервера | Наличие двух публичных ссылок |

Методичка на с. 34 запрещает Firebase полностью. Дополнительные
требования допускают Firebase Authentication, поэтому этот сервис
используется для аутентификации. Требование
собственной БД и сервера при этом сохраняется: они хранят и обрабатывают
задачи, а Firebase лишь подтверждает личность пользователя.
