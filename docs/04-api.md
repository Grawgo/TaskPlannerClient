# Контракт REST API

Базовый путь: `/v1`. Формат тела: JSON, кодировка UTF-8. Все маршруты,
кроме `/health`, требуют `Authorization: Bearer <Firebase ID token>`.
Сервер проверяет токен и получает UID; регистрация и вход происходят
напрямую через Firebase Authentication в Android-клиенте.
Строка `app_users` создаётся при первом любом защищённом запросе, поэтому
после входа клиент может сразу запросить список задач.

| Метод и путь | Назначение | Успех |
|---|---|---|
| `GET /health` | Проверка доступности сервера | `200` |
| `GET /me` | UID текущего пользователя, создание строки профиля при первом входе | `200` |
| `GET /tasks` | Список, фильтры и поиск своих задач | `200` |
| `POST /tasks` | Создание задачи | `201` |
| `GET /tasks/{id}` | Подробности своей задачи | `200` |
| `PUT /tasks/{id}` | Полное обновление своей задачи | `200` |
| `DELETE /tasks/{id}` | Удаление своей задачи | `204` |

## Список и поиск

`GET /tasks?query=отчёт&status=ACTIVE&priority=HIGH&sort=dueAt&order=asc&limit=20&offset=0`

Все параметры необязательны. `query` ищет совпадение без учёта регистра в
названии и описании. Пустой запрос равен отсутствию поиска. Фильтр
`status=ACTIVE` включает `TODO` и `IN_PROGRESS`; без фильтра показываются
все статусы. Возможные
значения `sort`: `dueAt`, `updatedAt`; `order`: `asc`, `desc`.
`limit` по умолчанию 20, максимум 50; `offset` по умолчанию 0.
При равных значениях сортировки сервер добавляет `id` как стабильный
второй ключ. При сортировке по сроку задачи без срока идут последними.

Ответ:

```json
{
  "items": [
    {
      "id": "eb5e96ce-e5bc-4f74-850b-97bf175d6f30",
      "title": "Подготовить доклад",
      "description": "Собрать 5–7 слайдов",
      "dueAt": "2026-10-02T15:00:00Z",
      "priority": "HIGH",
      "status": "IN_PROGRESS",
      "completedAt": null,
      "createdAt": "2026-09-26T09:00:00Z",
      "updatedAt": "2026-09-26T11:00:00Z"
    }
  ],
  "total": 1,
  "limit": 20,
  "offset": 0
}
```

Если совпадений нет, `items` — пустой массив и `total` — 0.

## Создание и изменение

Тело `POST /tasks` и `PUT /tasks/{id}` одинаково:

```json
{
  "title": "Подготовить доклад",
  "description": "Собрать 5–7 слайдов",
  "dueAt": "2026-10-02T15:00:00Z",
  "priority": "HIGH",
  "status": "IN_PROGRESS"
}
```

`description` и `dueAt` допускают `null`; сервер нормализует описание к
пустой строке. `title` обязателен, после обрезки пробелов — 1–120 символов.
`description` — максимум 2000 символов. Время в API передаётся в UTC,
формат RFC 3339. Владелец и даты создания/обновления устанавливаются
сервером. При переходе в `DONE` устанавливается `completedAt`; при выходе
из `DONE` поле очищается.

## Ошибки

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Название задачи не может быть пустым",
  "requestId": "01JQX6M0J2NHP8D5F4W8TAX8ZR"
}
```

| HTTP | Когда |
|---|---|
| `400` | Некорректное тело, фильтр или параметр |
| `401` | Нет токена или токен не прошёл проверку |
| `404` | Задача не существует либо принадлежит другому пользователю |
| `500` | Неожиданная ошибка сервера |
| `503` | База данных временно недоступна |

`404` одинаков для отсутствующей и чужой задачи, чтобы не раскрывать
существование чужих записей. Клиент показывает кнопку «Обновить» при
сетевой ошибке, `500` или `503` и повторяет исходный запрос.
