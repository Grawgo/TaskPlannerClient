# Планировщик задач — Android-клиент

Android-приложение для управления личными задачами. Интерфейс реализован на
Jetpack Compose с Material 3. В проекте используются Clean Architecture,
Navigation Compose, Hilt, Retrofit, Room и DataStore.

## Возможности

- Список задач с фильтрацией и сортировкой.
- Поиск задач с локальной историей запросов.
- Просмотр, создание и редактирование задачи с указанием срока, приоритета и статуса.
- Светлая и тёмная темы с сохранением выбора.
- Регистрация, вход, восстановление пароля и сохранение сессии через Firebase Authentication.

Задачи хранятся на отдельном Ktor-сервере. Room используется для истории
поиска, DataStore — для настроек оформления. Требования, архитектура,
контракт API и макеты экранов находятся в каталоге [docs](docs/).

## Сборка и запуск

Проект открывается в Android Studio. Для сборки из терминала:

```bash
./gradlew :app:assembleDebug
```

Требуются JDK 17 или новее и Android SDK с платформой API 35. Путь к SDK
задаётся в локальном файле `local.properties`, который исключён из Git.

Отладочная сборка использует API по адресу `http://10.0.2.2:8080/` для
подключения Android Emulator к серверу на компьютере разработчика. Адрес
настроен в `app/build.gradle`. Для выпуска приложения требуется адрес
опубликованного HTTPS-сервера.

## Firebase Authentication

Клиент использует HTTPS API Firebase Authentication для входа по почте и
паролю. Firebase используется только для учётных записей и выдачи ID-токенов.
Задачи хранятся в PostgreSQL на Ktor-сервере; Firestore и Realtime Database
не используются. Сессия сохраняется на устройстве в зашифрованном виде.

Для работы входа требуется файл `firebase.properties` с Web API key
Firebase-проекта и его идентификатор в конфигурации сервера. Порядок настройки
описан в [инструкции](docs/08-firebase-setup.md). Без ключа приложение
собирается и показывает состояние ненастроенной авторизации.

Результаты сборки, тестов и сценарии проверки приведены в
[протоколе тестирования](docs/09-testing.md).
